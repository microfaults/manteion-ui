# manteion-ui

Operator console for faults-lab: a React 18 + Vite + TanStack Router/Query single-page app that talks to manteion-go's `/api/v1` and, for the dashboard tiles, to Prometheus. With `VITE_USE_MOCK=true` it runs entirely on fixtures, which is how the public static demo is built.

## Commands

pnpm is the only package manager (`packageManager: pnpm@10.33.0`, `pnpm-lock.yaml`, build-script allowlist in `pnpm-workspace.yaml`). Do not run npm or yarn: they ignore that lockfile and write their own.

```bash
corepack enable pnpm     # once
pnpm install             # CI: pnpm install --frozen-lockfile
pnpm dev                 # Vite on :5173, or $PORT
pnpm lint                # biome check src
pnpm typecheck           # tsr generate && tsc -b --noEmit
pnpm test                # vitest run
pnpm build               # tsr generate && tsc -b && vite build
pnpm build:demo          # the same in mode demo: reads .env.demo (mock on), output is the static demo
pnpm format              # biome format --write src
```

- `src/routeTree.gen.ts` is generated by `tsr generate` and gitignored; run `pnpm typecheck` or `pnpm build` after adding or renaming a route file.
- CI is GitHub Actions (`.github/workflows/ci.yml`): lint, typecheck and test, then `pnpm build` and `pnpm build:demo`, on pull requests and on pushes to `mock-mode`, `develop` and `main`. A push to `mock-mode` also deploys the demo build to the Cloudflare Pages project `manteion`, but only while the repository variable `DEPLOY_ENABLED` is `true`. `.gitlab-ci.yml` is the legacy pipeline (merge-request pipelines only).
- Vitest pins `VITE_USE_MOCK=false` so tests exercise the real fetch path whatever `.env.local` says, and it excludes `**/.claude/**` so nested worktrees do not leak test files in.

## Environment and modes

All `VITE_*` variables are baked into the bundle at build time.

- `VITE_USE_MOCK=true` (set it in `.env.local`, or build with `pnpm build:demo`) serves fixtures for every API module and for the Prometheus dashboard bundle. Unset or `false` talks to a real manteion. API modules each read the variable into a local `USE_MOCK`; components gate on `IS_MOCK` from `src/lib/env.ts`.
- In a mock build `/` is the public landing page and the console carries a "Simulated data" bar; in an operator build `/` redirects to the dashboard and neither exists.
- `VITE_MANTEION_URL` defaults to same-origin; in dev, Vite proxies `/api` to `http://localhost:9090`.
- The browser queries Prometheus directly, not through manteion: `src/lib/prometheus.ts` fetches `VITE_PROMETHEUS_URL` (default `http://localhost:9091`); in dev `/prometheus/api/*` is proxied to `127.0.0.1:9091`.
- `docs/ops/` (ssh tunnels and `kubectl port-forward` on vm1) and the README links into it target the retired VM1; read them as history.
- `VITE_GRAFANA_URL` turns on Grafana links; `VITE_GRAFANA_EMBED=true` embeds panels and needs `allow_embedding` on the Grafana side. `VITE_DEFAULT_ENV` and `VITE_OPERATOR` are display defaults.

## Where the code misleads

Mock mode (`src/lib/api/mock-experiments.ts`, `mock-fixtures.ts`, the mock branches in `src/lib/api/*.ts`). Every mutating call has a mock branch, and state lives in module memory, so a page reload resets it:

- Start and resume are instant in the mock. The real backend blocks up to `MANTEION_CONVERGE_TIMEOUT` (30 s), can answer an experiment start with 202 while its first phase has already failed, and answers resume or phase start with `504 not_converged`.
- A phase the mock engine drives lasts a fixed 8 s (`MOCK_PHASE_STEP_MS`) while its results claim `rps × duration_sec` requests; such phases carry an `accelerated` tag. Fixture phases never tick.
- Result numbers are generated, with one exception: the sample experiment (`exp-sample-catalog-latency`) replays the figures recorded on the real testbed (`SAMPLE_RECORDED_RESULTS`), and only while its phases, rules and workflows are unmodified, `rule-014` is enabled and the phase ran to its natural end. The `synthetic` and `recorded` labels come from `phaseProvenance`, which reads what the engine actually stored. Never label a generated number as measured.
- The mock answers validation failures with 400 where the backend uses 422, and it accepts `persist_cache` plus frozen services in one phase (real: 422).
- Mock instance timestamps are ages stamped on every read, and an instance's `active_rule_ids` are derived from the mock rule store, which the mock kill switch really changes.

Real backend:

- Dashboard request rate and p99 come from spanmetrics `calls_total` without a `span_kind` filter, so they count client and server spans (roughly double). Grafana's dashboards use atropos's `http_server_*` metrics instead, so UI tiles and Grafana panels disagree. The cache-hit tile uses atropos's `atropos_cachebox_*` counters (`CACHE_HIT_PROMQL`).
- The UI targets manteion `feat/atropos-daemon`, but `docs/api/api-needed.md` still describes much of the older push-era `develop` backend. Main differences: no pushes; start, resume and phase start can block; new 422s for `persist_cache` plus freeze and for cache-box key-strategy disagreement, which the wizard's preflight does not check.
- The UI never branches on the error `code`; `describeApiError` (`src/lib/api-errors.ts`) prints it, and the `lagging`/`suspect` lists of a 504 are not shown separately.
- The rule builder sends `match_ast`, which the backend drops (no such field). The README's "OPA-rego rules builder" is unrelated to the backend's `/api/v1/opa/policies` harness.
- Two `MatchNode` types exist: the wire one in `src/types/api.ts` and the UI one with an optional `id` in `src/lib/rego/ast.ts`. `rule-editor-panel.tsx` bridges them with an unchecked `as MatchNode` cast.
- The kill switch acts on the whole service and also cancels its fault configs; the dialog says so, but the response's `cancelled_fault_config_ids` is dropped by the Zod schema.
- The instance panel shows `observed_generation`, `applied_generation` and `observed_errors`. The backend's `replay_set_state`, `host` and `capabilities` are still stripped by the Zod schema. A rule shows as active from `enabled` alone, and an enabled rule attached to no phase is live immediately.
- Queries that poll only while something is live must fetch once more when it ends (`src/lib/use-final-refetch.ts`, and the finished-phase count in the experiment rollup's query key); otherwise the last result never arrives.
- `/runs` routes only redirect to `/phases`; a "run" is a phase.

## Conventions

- When driving a live backend by script, never click "the first button in a row": rules rows hold a live enable switch, and the service panel's kill switch is one click away. Click a named target and diff rule state (`enabled`, `updated_at`) before and after.
- Every API call goes through `src/lib/api/client.ts` (Zod-validated fetch). Add endpoints in `src/lib/api/<resource>.ts` and list them in `docs/api/api-needed.md`. Server state lives in TanStack Query, route state in the URL; no Redux.
- Public demo plan, decided 2026-11-15: the mock build ships first as a static site on Cloudflare Pages (`pnpm build:demo`, deployed by CI from `mock-mode`; live at https://manteion.pages.dev since 2026-11-18); live mode later uses same-origin `/api`, and `src/lib/prometheus.ts` then needs an absolute base URL. Pages serves the single-page fallback only while `dist/` has no `404.html`.
- Commits use conventional-commit subjects with a scope (`fix(experiments): ...`); one commit per request, files staged by name. The owner manages branches and merges, so do not push or open pull or merge requests unless asked; when asked to push, use `github`.
- `docs/` (design/, api/, ops/) describes current reality only. Brainstorming specs and implementation plans stay local under the gitignored `docs/superpowers/`; when work ships, update the knowledge-base doc instead of committing the plan. `.claude/` is gitignored.
